# 01 · 功能裁剪：从 Veyra 2.1.0 到 Vela

上游：[Likely7/Veyra-NRVideo](https://github.com/Likely7/Veyra-NRVideo)，2026-10-19 发布的 2.1.0，GPL-3.0。

Vela 只做一件事：把 Elgato 4K Pro 采集到的 PS5 / Switch 2 画面，在 RTX 5070 Ti 上用 DLSS 帧生成补帧后输出。功能按优先级排列：

1. 补帧（DLSS 帧生成，2×–6×）
2. 延迟监控
3. 超分辨率
4. HDR
5. 自动调色

这五项之外的功能都不做。另外保留了音频直通（采集卡声音 → 默认输出）。它不算一项功能，但没有它播放器就没有声音。

## 做法：重写骨架，移植零件

上游约 11.4 万行（src / include / apps / qml / shaders）。其中 `QmlPlayerBridge.cpp` 有 9033 行，`EnhanceGraph.cpp` 3710 行，`EngineController.cpp` 2870 行，NR、FSR、XeSS、导出、节点编辑等功能都缠在这几个文件里。在这几个文件上做减法，删到最后每一行都得重新验证，而且没法在不跑硬件的情况下确认删干净了。

所以 Vela 重写了引擎骨架、管线、呈现和界面，只把上游已经在真机上验证过、而且边界清楚的模块移植过来（改了命名空间和日志，去掉了与本机无关的分支）。新代码约 7700 行（核心 1000 + Windows 5000 + 着色器 360 + 界面 1260），不含测试。

## 保留并移植的部分

| 上游文件 | Vela 文件 | 改动 |
|---|---|---|
| `ngx/NgxCoreHost` | `win/src/nv/NgxCore` | 单设备单 NGX 核心、全部 SEH 保护，保留；去掉测试注入 |
| `ngx/DlssFgBackend` | `win/src/nv/DlssFg` | 视频用的静止相机矩阵、资源声明、运动矢量缩放约定原样保留；去掉 RTX 30/40 解锁（见下） |
| `ngx/DlssgLite.h` | `DlssFg` 的 `performanceMode` | DLSS-G 310.9.16 的轻量候选混合参数，上游在 RTX 5070 实测 4× 批次 5.6 → 2.8 ms |
| `ngx/DlssSrBackend` | `win/src/nv/DlssSr` | 只用于 HDR10 画面（线性 FP16），全分辨率运动矢量 |
| `ngx/VideoSrBackend`、`TrueHdrBackend` | `win/src/nv/RtxVideo` | RTX Video SDK 的 VSR 与 TrueHDR，参数与资源状态约定照搬 |
| `ngx/NvOfSession` | `win/src/nv/NvOf` | 硬件光流；去掉反向光流与故障注入 |
| `gfx/ReflexSession.h` | `win/src/nv/Reflex.h` | 只开低延迟模式和打标记，**不调用 Sleep**（采集画面的到达时间由主机决定，Sleep 只会加延迟） |
| `source/ElgatoHdrControl` | `win/src/capture/Elgato` | Elgato 私有属性：HDMI HDR InfoFrame、卡上色调映射开关、非 MK.2 卡 P010 色度全范围的修正。改为通过 Media Foundation 源上的 `IKsControl` 访问 |
| `engine/LivePairLatency`、`PresentationScheduler` 的思路 | `core/FramePacer` | 重写：每批按自身到达时间锚定，迟到的生成帧丢弃，真实帧不丢 |
| `shaders/Nv12Upload`、`NvofDensify`、`YuvToLinearRgb` 的思路 | `win/shaders/CaptureToWorking`、`FlowToMotion` | 重写并合并：一次读取原始字节，同时产出工作纹理和光流输入 |

## 删除的部分

**DLSS 5 / 神经渲染降噪（NR）适配**，按你的要求整块去掉：
`NrInstance`、`NrTemporalPass`、`NrHoldPass`、`NrResidualComposite`、`DlssNrRuntimeAdapter`、`AutoNrController`、NR 预设与“画面控制”、NR 保护区域、RenoDX parity 编解码、`config/nr-default.json`。

**与 RTX 5070 Ti 无关的 GPU 路径**：

- RTX 30/40 的多帧生成解锁：`AdaMfgUnlock`、`AmpereMfgUnlock`、`NvapiArchSpoof`、`DlssgTransfusion`、`FgCompatibilitySession`、`hde64` 反汇编器。这些代码会修改 NVIDIA 运行库的内存，Blackwell 原生支持多帧生成，不需要它们。
- AMD：FSR 超分 / 帧生成、AMD 光流、lmxxf NR、HIP。
- Intel：XeSS、XeSS 多帧解锁与节奏器。
- CUDA 插帧后端 `VfgBackend`、GPU-DIS 光流兜底。

**与 Elgato 4K Pro 采集无关的输入源**：
本地文件播放（FFmpeg 解复用 / 解码、字幕、去隔行、网络流）、PS5 Remote Play（Chiaki）、Moonlight / Sunshine、Xbox 串流（WebRTC）、屏幕捕获与游戏模式、Magewell、DeckLink、AVerMedia 厂商音频与切换、通用 DirectShow 采集与 MJPEG / H.264 压缩采集解码。

**其他功能**：
导出（NVENC / Media Foundation 编码、导出队列）、截图与图片导出、预设库、调色套件（曲线、色轮、LUT、调色预设）、美颜与人脸网格、抗锯齿（FXAA / SMAA / MLAA）、节点编辑器与列表模式、四语言界面（只保留简体中文）、更新检查、赞助页面、OBS 游戏捕获兼容、RTSS 兼容、抖音直播伴侣检测、手柄转发、杜比 / DTS 码流直通（只保留 PCM）。

**界面**：Qt Quick / QML 整套去掉，换成 WebView2 承载的 HTML 界面（理由见 [02](02-后端架构.md#界面层)）。

## 新增的部分

上游没有、Vela 为这五项功能补上的：

- **自动调色**（`core/AutoColor` + `Analysis.hlsl` + `ColorApply.hlsl`）。上游的“自动”只是 NR 的画面控制，不是独立的调色。Vela 的六个预设（自然 / 去灰 / 压高光 / 降饱和 / 提亮暗部 / 去偏色）只是自动修正的起点，加上按画面推荐，不是上游那套手动调色预设。
- **按批锚定的帧节奏**和“低延迟”节奏模式（`core/FramePacer`）。
- **延迟分解与端到端估算**（`core/LatencyMonitor`），包括采集卡 / 显示器延迟校准和补帧额外延迟的单独显示。
- **画面内延迟角标**由 GPU 直接画进视频（`Compose.hlsl`），界面隐藏时覆盖窗口完全关闭，视频窗口可以走独立翻转。
- **音画同步**：音频延迟跟随实测的视频管线延迟。
- **管线规划器**（`core/ModePlanner`）：根据信号、显示器和驱动能力决定超分引擎、HDR 路线和可用倍数，可在任何平台上测试。
